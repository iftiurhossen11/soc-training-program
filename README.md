## 🎯 Training Objectives

This program focuses on developing practical skills in the following areas:

- **SIEM & Log Analysis:** Working with Splunk, searching security events using SPL, and exploring alerting workflows.
- **Network Forensics:** Analyzing packet captures and network traffic with Wireshark and NetworkMiner.
- **Endpoint & Malware Analysis:** Learning static analysis, system monitoring, and safe investigation techniques.
- **Threat Hunting:** Investigating suspicious activity and mapping relevant behavior to MITRE ATT&CK.
- **Cyber Threat Intelligence:** Enriching Indicators of Compromise (IoCs) using public threat-intelligence resources.
- **Automation:** Exploring Python-based IoC enrichment and security workflow automation.

*Note: The objectives above describe the program's learning goals. Individual skills should be marked as completed only after the corresponding exercises have been performed and verified.*

## 📅 Methodology & Study Plan

The recommended **Standard Track** provides a structured six-month learning schedule.

- **Duration:** 6 months
- **Recommended commitment:** 13–15 hours per week

### My Four-Step Learning Loop

1. **📖 Theory & Research:** Study cybersecurity fundamentals, vendor documentation, and threat reports.
2. **🧪 Hands-On Practice:** Work through labs in isolated virtual machines and collect relevant logs.
3. **📝 Documentation:** Record procedures, observations, evidence, IoCs, and investigation findings.
4. **🛡️ Detection Engineering:** Map relevant behavior to MITRE ATT&CK and develop or test suitable SPL or Sigma detection rules.

---

## ⚠️ Lab Safety & Ethical Guidelines

- **Isolated Environment:** Perform malware analysis and security testing in appropriately isolated virtual machines. Use host-only networking where suitable, and disable network access when required for the exercise.
- **Authorized Testing:** Scan, test, or assess only systems you own or have explicit permission to assess.
- **Safe Samples:** Do not commit live malware samples, credentials, API keys, or other sensitive artifacts to the repository.
- **Threat Intelligence:** Treat public reputation results as investigative evidence, not definitive proof that an IP, URL, file, or domain is safe or malicious.
- **Responsible Documentation:** Clearly label simulated events, sample outputs, and hypothetical findings. Do not present them as real attacks or verified detections.

## 💡 Key Learnings & Takeaways

1. **The Power of Logs:** Security logs provide valuable evidence for identifying suspicious activity and investigating incidents.
2. **Context Is Essential:** IP addresses, file hashes, and other IoCs become more useful when enriched with reliable threat intelligence and supporting evidence.
3. **Proactive Defense:** Threat hunting can help identify suspicious behavior that automated detections may miss.
4. **Automation With Verification:** Python and SOAR workflows can reduce repetitive tasks, but automated actions require testing, safeguards, and appropriate oversight.
5. **Documentation Matters:** Reproducible steps, accurate timestamps, and clear evidence make security investigations easier to review and communicate.
