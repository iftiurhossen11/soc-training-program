# Contributing to SOC Analyst Training Program

First off, thank you for considering contributing to this project! It's people like you who make the cybersecurity community a fantastic place to learn, collaborate, and grow.

We welcome contributions that improve the quality of the documentation, practical labs, detection rules, investigation workflows, and learning resources.

## How Can I Contribute?

### Reporting Bugs

If you find a bug, an incorrect explanation, a broken link, or an issue with a lab:

- Check the GitHub Issues section to ensure the problem has not already been reported.
- If no existing issue addresses the problem, open a new issue.
- Provide a clear title and detailed description of the problem.
- Include relevant steps to reproduce the issue, expected behavior, actual behavior, and sanitized error messages or screenshots when applicable.
- Never include passwords, API keys, access tokens, personal information, or confidential logs in a public issue.

### Suggesting Enhancements

To suggest a new feature, lab, tool, or improvement:

- Open a new GitHub issue with a clear title and description.
- Explain the problem your suggestion would solve and why it would benefit learners.
- Include examples, references, or a proposed implementation when helpful.
- For substantial changes, discuss the idea with the project maintainer before investing significant effort.

### Contributing Practical Labs

Contributions to practical cybersecurity exercises are especially welcome.

- Provide clear objectives, prerequisites, required tools, and step-by-step instructions.
- Include expected results and troubleshooting guidance where appropriate.
- Use authorized, isolated lab environments and safe sample data.
- Clearly distinguish simulated events and example outputs from results obtained during actual testing.
- Include screenshots or logs only when they support the explanation and do not expose sensitive information.
- Cite external resources and respect their licenses and usage restrictions.

### Submitting Pull Requests

1. Fork the repository.
2. Create a descriptive branch from `main`.
3. Make your changes using the existing project structure and style.
4. Add or update tests when applicable to code changes.
5. Run relevant tests and verify that your instructions and examples work as intended.
6. Check Markdown formatting, links, code blocks, and spelling.
7. Update relevant documentation when your changes affect existing features or labs.
8. Commit your changes with a clear and descriptive commit message.
9. Open a pull request against the repository's `main` branch.
10. Describe what changed, why it is needed, and how you verified it.

Please keep pull requests focused on a specific improvement whenever possible.

## Style Guide

To maintain consistency throughout the repository:

- Use clear and descriptive commit messages.
- Follow the existing directory structure, naming conventions, and formatting.
- Use Markdown headings, lists, tables, and code blocks appropriately.
- Explain technical concepts in clear, beginner-friendly language.
- Include comments in scripts where they improve understanding.
- Document prerequisites, commands, expected outputs, and troubleshooting steps.
- Verify commands and detection queries before presenting them as tested.
- Do not claim that a lab, scan, detection, or investigation was completed unless it was actually performed and verified.

## Cybersecurity Safety Guidelines

Because this project focuses on cybersecurity education:

- Perform testing only on systems and networks you own or are explicitly authorized to assess.
- Do not contribute instructions intended to compromise unauthorized systems, steal credentials, or deploy malware against real targets.
- Use isolated virtual machines, approved test environments, and appropriate sample datasets.
- Do not publish sensitive information, private keys, credentials, or confidential organizational data.
- Follow the relevant tool licenses, dataset terms, and applicable laws.

## Code of Conduct

By participating in this project, you agree to abide by our [Code of Conduct](CODE_OF_CONDUCT.md).

Unacceptable behavior may be reported according to the procedures described in that document.

## Questions?

If you have questions or need clarification, open an issue in the [SOC Analyst Training Program repository](https://github.com/iftiurhossen11/soc-training-program).

Thank you for helping improve this project and supporting the cybersecurity learning community!

**Learn together. Share responsibly. Improve security.**
